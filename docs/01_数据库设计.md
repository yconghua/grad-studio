# GradStudio 数据库设计（第一步产物）

> 版本：v1.0（六项决策已确认，表结构**已落地**为 `.sql` 文件）
> 对应需求：研究生工作室管理平台 12 个业务模块
> 落地位置：`electron/db/schemas/`
> 落地方式：每个业务域一个 `NN_域名.sql`；升级 `package.json` 的 version 后重启即自动建表 / 自动补列
> 落地结果与静态校验记录见第六节

---

## 一、设计约定（先看这一节，后面字段都按它来）

| # | 约定 | 说明 |
| --- | --- | --- |
| 1 | **多机共用同一个 MySQL** | 所有主键用 `INT UNSIGNED AUTO_INCREMENT`；唯一性靠数据库层的 `UNIQUE KEY` 保证，不依赖前端判断 |
| 2 | **时间统一由数据库生成** | 时间列用 `DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`，业务时间（如请假开始时间）由用户选。**不信任前端传来的"现在"**——多台电脑时钟不一致会串数据 |
| 3 | **金额** | 统一 `DECIMAL(12,2)`，绝不用 `FLOAT`（浮点算钱会出错） |
| 4 | **不使用物理外键** | 沿用现有 `BaseRepository` 的轻量风格，只用逻辑关联 + 普通索引；避免多机并发写入时的外键锁等待 |
| 5 | **状态字段** | 统一 `VARCHAR(20)`，取值写在列注释里；下拉选项由 `sys_dict` 数据字典驱动，加状态不用改表 |
| 6 | **逻辑删除** | 除用户表外，主数据表加 `is_deleted TINYINT DEFAULT 0`，删除走逻辑删除（多机场景下误删无法回滚） |
| 7 | **文件附件（Q6）** | 本期不做上传。所有涉及附件的表**不建文件列**，页面上附件按钮统一提示"该功能正在开发中" |
| 8 | **定位 / 扫码（Q10）** | 本机桌面端不做。相关入口提示"正在开发中"，但 `attendance.sign_type` 等字段预留取值 |
| 9 | **权限极简（Q4）** | 只有 `admin` / `user` 两个角色，且差异仅"能否进系统管理"。因此**不建角色表、权限表、用户角色关联表** |
| 10 | **审批统一（Q5）** | 入组 / 离组 / 请假 / 报销 / 设备借用 / 成果审核 全部走 `approval_order` + `approval_record`。审批人 = 任意管理员，单级审批 |
| 11 | **成员身份不参与权限（Q3）** | 「导师 / 博士 / 硕士 / 本科 / 访客」只是 `member.member_type` 字段，用于展示和筛选。导师的权限靠 `user.role = admin` 获得 |
| 12 | **SQL 限制** | 执行时按 `;` 拆分，**不能写触发器 / 存储过程**（内部含分号会被切碎） |

## 七、落地时对本文档的 4 处列名微调

写 SQL 时发现 4 个列名与数据库关键字重名，虽然反引号包裹后能正常执行，但一旦将来有人写裸 SQL 或换数据库就会踩坑，故做了重命名。**功能与字段含义完全不变**：

| 原设计列名 | 落地列名 | 所在表 | 重命名原因 |
| --- | --- | --- | --- |
| `date` | `attend_date` | `attendance` | `date` 是数据类型关键字，裸用易歧义 |
| `shift` | `duty_shift` | `duty_schedule` | 与 `duty_date` / `duty_type` 命名保持一致 |
| `year` | `budget_year` | `budget` | `year` 是数据类型关键字 |
| `scope` | `notice_scope` | `notice` | `scope` 在多数据库中是保留字 |

另：`achievement.partition` 是 MySQL 保留字，**保留原名**（字段语义无法替代），在 SQL 中已用反引号包裹并在文件注释中标注。

# grad studio · 使用手册

> **GradStudio（研究生工作室管理平台）是一个面向高校研究生工作室与课题组的综合管理平台，帮助导师和管理员实现成员、项目、任务、组会、周报、成果、文档与日常事务的一体化管理。**（Electron + Vue 3 + MySQL）
> 不需要自己搭后端服务：Electron 主进程直连你的 MySQL，登录即用。
> 内置账号体系、角色权限（管理员 / 导师 / 学生）、数据库连接管理（**自动建库建表**）、系统管理，业务模块可自由扩展。

## 这是什么
（[↑ 回到目录](#toc)）

GradStudio 是一个本地运行的桌面应用框架：**下载源码 → 装依赖 → 启动 → 填一次数据库连接 → 登录使用**。数据全部落在你自己的 MySQL 里，没有云端、没有第三方服务。

**开箱即用的能力：**

| 能力 | 说明 |
| --- | --- |
| 账号体系 | 登录 / 会话 / 修改密码 / 用户管理；**三级角色（管理员 / 导师 / 学生）+ 首次登录强制改密** |
| 导师关联 | 学生可指定「指导导师」，导师默认只看自己名下学生的周报 / 毕业进度 |
| 数据库连接管理 | 支持多套 MySQL 连接、运行时切换；**添加连接时自动建库 + 建表 + 写入默认管理员** |
| 业务管理 | 科研项目、论文专利、课题经费、工位设备、考勤排班、组会活动、**周报管理、任务看板、组会日历**、讨论区审批、资源文档等 30+ 业务模块 |
| 消息中心 | 业务事件自动通知（审批结果 / 任务分配 / 活动报名 / @ 我 / 周报批注 / 组会提醒），未读计数、点击跳转、导师 / 管理员可手动发消息 |
| 系统管理 | 日志审计、数据备份、系统参数、关于系统（版本 / 数据库信息 / 开发者工具 / 清理缓存 / 检查更新） |
| 数据驱动导航 | 左侧导航由配置文件驱动，加页面不改框架代码 |

## 快速开始：两条命令跑起来
（[↑ 回到目录](#toc)）

在项目根目录（含 `package.json` 的目录）打开终端：

```bash
# 第 1 步：安装依赖（首次需要，约 1~3 分钟）
npm install

# 第 2 步：启动开发模式（自动打开应用窗口）
npm run dev
```

启动后会出现 Electron 窗口并停在**登录页**——**此时还没有任何数据库连接，需要先完成下面的「添加数据库」才能登录。**

## 首次使用：添加数据库（自动建库建表）
（[↑ 回到目录](#toc)）

**系统不内置任何默认连接**，首次使用必须自己添加一个。整个过程不需要手写 SQL：

1. 在登录页点击「添加数据库」；
2. 填写你的 MySQL 连接信息（主机 / 端口 / 用户名 / 密码 / 数据库名）；
3. 点击确认，主进程会自动完成：
   - **建库**：`CREATE DATABASE IF NOT EXISTS`（不存在才创建，字符集 utf8mb4）；
   - **建表**：按文件名顺序执行 `electron/db/schemas/` 下的全部 `.sql`（35 张表，见 [数据库表清单](#数据库表清单)）；
   - **写默认管理员**：账号 `admin`，密码 `admin123456`；
4. **添加的第一个连接会自动生效**，返回登录页用默认账号登录即可（登录后强制修改密码，见 [角色与权限体系](#角色与权限体系)）。

**几个关键约定：**

- 数据库的连接信息保存在应用所在电脑的**用户数据目录**（`db-connections.json`），**不会进入代码仓库**，换机器需重新添加；
- 添加第二个连接后，可在「系统设置 → 关于系统」里随时切换，多套连接运行时切换、无需重启；
- ⚠️ **新表不会在普通重启时自动建**。给「已存在」的数据库加表 / 加列，只有两种触发时机：① 再添加一个新的数据库连接；② 升级 `package.json` 的 `version` 后重启一次。升级迁移会**重跑全部 `.sql`**（新表用 `CREATE TABLE IF NOT EXISTS` 创建），并自动比对每个 `.sql` 声明的列与库中实际列，**缺失的列自动 `ALTER TABLE ... ADD COLUMN` 补齐**；全部库都成功后才写入新版本号，中途失败则下次启动自动重试（已完成的操作幂等跳过，不会重复执行）。想立即生效也可直接在 MySQL 客户端手动执行 SQL。

## 角色与权限体系
（[↑ 回到目录](#toc)）

系统内置**三级角色**（`shared/constants.js` 单一事实来源）：

| 角色 | 说明 | 默认密码 |
| --- | --- | --- |
| 管理员 admin | 全部权限：用户管理 / 系统设置 / 统计报表 / 全量数据 | `admin123456` |
| 导师 mentor | 管理自己名下学生：审批、周报批注、组会、发消息等 | `ds123456@` |
| 学生 student | 个人事务：周报、任务、组会、活动报名、借用等 | `xs123456@` |

> 历史角色「普通用户 user」仅做兼容，权限与导航按「学生」处理，不再提供新增入口。

**核心规则：**

| 场景 | 规则 |
| --- | --- |
| 首次登录 | `must_change_password` 标志强制跳转改密页，**改密后才能进入主界面**；重置密码 / 批量导入的用户同样首次强制改密 |
| 重置密码 | 管理员在成员管理中重置，按角色重置为对应默认密码 |
| 导师关联学生 | 用户表 `advisor_id` 指向导师；新增 / 编辑 / 批量导入均可指定「指导导师」；导师登录后成员管理、周报、毕业进度**默认只看自己名下学生** |
| 成员管理 | 导师 / 管理员可见；导师**只能查看成员与发消息，不能新增 / 编辑 / 删除**（新增仅管理员） |
| 统计报表 / 系统设置 | **仅管理员**可见（导师也不行） |
| 讨论区 | 帖子删除：管理员可删任何人的；导师 / 学生只能删自己的 |
| 任务协作 | 管理员全权限；导师 / 学生只能编辑**自己创建或被分配**的任务；删除仅管理员 / 创建人 |
| 物品借用 | 列表：学生只看自己借的，管理员看全部；改 / 删仅本人或管理员 |
| 审批中心 | 列表：学生只看自己发起的，导师 / 管理员看全部；审批仅导师 / 管理员；**撤销仅申请人本人或管理员** |
| 周报 | 列表：管理员全部、导师看自己学生、学生只看自己；改 / 删仅本人或管理员 |
| 消息中心 | 手动发消息仅导师 / 管理员；学生只能看自己的消息 |
| 入组离组 | 学生只看自己的申请，导师 / 管理员看全部并审核；撤销仅本人或管理员 |

> 以上为接口层校验（后端强制），前端按钮同步按角色隐藏。

## 核心业务功能
（[↑ 回到目录](#toc)）

### 周报 / 任务闭环
- 学生按周提交周报（本周进展、遇到问题、下周计划），同一人同周不重复提交；
- 导师在线批注、打分（0-100），可**一键转为待办任务**指派给具体学生；
- 任务看板四列拖拽：待办 / 进行中 / 已完成 / 延期（截止日已过未完成自动归入延期）；
- 任务支持优先级、截止日期、标签、**@ 成员**（被 @ 者收到站内消息 + 桌面通知）、评论；
- 自动通知：任务分配、@ 我、周报批注、审批结果、活动报名成功、组会提醒等均自动写消息中心。

### 组会 / 学术活动
- 组会排期（时间、地点、主持人、类型、纪要）；
- **参会人选择器**：点击参会人弹出窗口，学生 / 导师分组罗列，勾选即时生效；
- **已读回执**：参会人打开组会详情自动确认已读；导师可查看每位参会人是否已读，并**一键提醒未读成员**；
- **组会日历**：工作台「日程安排」手写月历视图，聚合组会、毕业里程碑、个人日程、任务截止日期，按角色过滤，点日历格子看详情。

### 消息中心
- 业务事件自动通知（见上），支持未读计数（顶部实时刷新，读后消失）、全部已读；
- 点击消息按类别跳转对应页面：任务 / 审批 / 周报 / 组会 / 活动 / 讨论区 / @ 我；
- **手动发消息**：导师 / 管理员在消息中心选择收件人发送；
- 系统桌面通知（Electron Notification API）保留。

### 成员管理与批量导入
- 单个新增：账号 / 角色 / 姓名 / 学号 / 导师等字段，创建后提示角色默认密码；
- **批量导入**：下载 CSV 模板（UTF-8 BOM，Excel 打开不乱码）→ 上传 → 前端逐行校验（必填项 / 角色枚举 / 导师账号存在性）→ 结果弹窗展示成功摘要 + 失败明细；单次最多 500 行，文件 ≤ 5MB。

### 工作台首页
- 统计卡片（成员数 / 任务数 / 待办 / 未读消息等）；
- 通知公告横向滚动条（有公告才显示，点击跳转通知公告页）；
- 最近组会展示（点击跳转组会页）；
- 快捷入口按角色过滤（学生不显示成员管理）。

## 打包成 exe / 安装包
（[↑ 回到目录](#toc)）

```bash
npm run pack
```

该命令 = `npm run build`（Vite 构建前端到 `dist/`）+ `electron-builder`（打包安装包）。

**输出目录**：`release/`（已被 `.gitignore` 忽略，不会提交到仓库）。Windows 下产出 NSIS 安装包（`.exe`）。

**注意事项：**

1. **建议用管理员终端执行**（右键终端 → "以管理员身份运行"）。electron-builder 在 Windows 上创建安装程序时需要写系统目录 / 符号链接的权限，普通终端偶发 `EPERM` / 权限错误；
2. 首次打包会下载 electron 二进制与 NSIS 工具，**耗时较长**，请耐心等待；国内网络慢可先配置镜像（见 [FAQ](#常见问题-faq)）；
3. 若被杀毒软件拦截生成的 exe，属于误报，添加信任或白名单即可；
4. 产物在 `release/` 下，把 `*.exe` 分发给别人即可，对方无需安装 Node / MySQL 客户端（但**运行仍需一个 MySQL 实例**，首次打开在应用里添加连接）。

**推送 main 分支自动发布（GitHub Actions）：**

仓库已内置 `.github/workflows/release.yml`：推送 `main` 分支到 GitHub 后，CI 会读取 `package.json` 的版本号——若该版本对应的 tag 尚不存在，则自动打 tag 并打包发布；版本号未变化则自动跳过。CI 在 Windows 环境执行 `npm ci` → `npm run build` → `electron-builder`，并把安装包上传为 **GitHub Release**。

**发版步骤：** 改 `package.json` 里的 `version` → 提交并推送：

```bash
git add package.json
git commit -m "chore: release v1.0.8"
git push origin main
```

tag 和 Release 全部自动完成，无需手动打 tag。也可以在 GitHub Actions 页面手动触发。CI 使用 `npm ci`，请确保 `package-lock.json` 已提交。

**应用内检查更新：** 「系统设置 → 关于系统」可手动检查更新：应用请求更新源仓库的 GitHub Releases 最新版本，与本地版本做语义化对比，发现新版本时展示更新说明并引导前往下载页。

> **前提：更新源仓库必须设为公开**（检查更新走 GitHub 匿名只读 API，私有仓库会返回 404），且已通过上面的流程发布过 Release。二次分发时，把 `electron/ipc/sys.js` 顶部的 `UPDATE_REPO` 常量改成你自己的 `owner/repo` 即可。

## 二次开发：加自己的业务模块
（[↑ 回到目录](#toc)）

一个业务模块涉及 8 处文件，数据流向：**页面 → api → preload → IPC → Service → Repository → MySQL**：

| # | 文件 | 作用 |
| --- | --- | --- |
| 1 | `electron/db/schemas/NN_表名.sql` | 建表 + 种子数据（升级版本号后自动执行） |
| 2 | `electron/db/repositories/xxxRepository.js` | 数据访问层（可复用 `crudFactory` 生成标准 CRUD） |
| 3 | `electron/services/xxxService.js` | 业务服务层（简单 CRUD 可直接用 `createCrudService` 工厂） |
| 4 | `electron/ipc/xxx.js` | IPC 通道（在 `electron/ipc/index.js` 注册） |
| 5 | `electron/preload.js` | 用 `createInvoke` 把通道暴露到 `window.api` |
| 6 | `src/api/index.js` | 前端 API 封装（调用 `window.api.xxx`） |
| 7 | `src/pages/xxx/` | 页面组件（标准 CRUD 可直接用 `CrudPage` 组件） |
| 8 | `src/config/navConfig.js` | 左侧导航注册（单一数据源，路由自动生成；页面组件在 `src/router/index.js` 的 `navPageMap` 注册） |

技术栈：Vue 3（`<script setup>`）+ Vue Router 4 + Vite 5 + Electron 31 + MySQL（mysql2）+ bcryptjs（密码哈希）。

**写权限模型（重要）：**

`createCrudService(repo, { label, write, creatorField })` 中的 `write` 取值：

| 取值 | 含义 |
| --- | --- |
| `manager` | 仅导师 / 管理员可写 |
| `member` | 所有登录用户可写（**无归属校验**，需要时手动加包装） |
| `self` | 只能操作 `ownerField` 指向自己的记录（导师 / 管理员不受限） |

**归属校验包装模板**（如任务 / 帖子删除、审批撤销）：

```js
const _remove = collab.xxx.remove
collab.xxx.remove = async (id) => {
  // ... 登录校验、读取记录
  if (!permission.isAdmin() && Number(row.owner_id) !== Number(permission.currentUserId())) {
    return { success: false, message: '无权限：只能操作自己的记录' }
  }
  return _remove(id)
}
```

**开发约定（踩坑记录）：**

1. **主进程改动必须完全重启应用才生效**：`electron/preload.js`、`electron/ipc/*`、`electron/services/*`、`electron/db/repositories/*` 的修改都要重启（`npm run dev` 重跑）；纯前端（`src/**`）改动热更新即可；
2. **改前端 Vue / JS 文件用编辑器整体读写**，不要用 shell 文本替换（历史中 `-replace` 多次损坏文件，出现 `r`n、变量未定义等诡异问题）；
3. 改完先 `node --check electron/**/*.js` 查后端语法、`npm run build` 验证前端，再交付；
4. 新增 IPC 通道后，检查 `preload.js` 与 `src/api/index.js` 是否都已暴露（历史多次因漏暴露导致"调用不存在"报错）；
5. 前端跨 IPC 传参时构造**普通对象**（避免 Vue reactive proxy 直接序列化导致异常）；
6. 角色 / 状态等枚举值统一在 `shared/constants.js` 声明，前端 `src/config/constants.js`、`src/config/fieldOptions.js` 引用，不要两端写死魔法值。

## 常见问题 FAQ
（[↑ 回到目录](#toc)）

**Q1：`npm install` 很慢 / 卡住？**
国内网络建议使用 npmmirror 镜像。在用户目录（`~/.npmrc`）写入：
```bash
registry=https://registry.npmmirror.com
electron_mirror=https://cdn.npmmirror.com/binaries/electron/
electron_builder_binaries_mirror=https://cdn.npmmirror.com/binaries/electron-builder-binaries/
```

**Q2：启动后白屏？**
开发模式请确认 5173 端口未被占用（`npm run dev` 输出里 Vite 正常起来）；打包版使用 hash 路由，一般不会白屏。可先清缓存（系统设置 → 关于系统 → 清理缓存）再试。

**Q3：添加数据库提示连接失败？**
- 确认 MySQL 服务已启动、端口正确；
- 确认账号密码正确且**有建库权限**（程序要执行 `CREATE DATABASE`）；
- 远程 MySQL 需确认账号允许从当前 IP 访问（`%` 或指定主机授权）。

**Q4：`npm run pack` 报权限错误？**
改用**管理员终端**重试（见「打包成 exe」注意事项第 1 条）。

**Q5：打包下载 electron 二进制超时？**
同样配置上面的镜像后重试；或把 `node_modules` 删掉重新 `npm install` 一次。

**Q6：默认密码是什么 / 忘记密码怎么办？**
- 默认密码按角色：学生 `xs123456@`、导师 `ds123456@`、管理员 `admin123456`，首次登录强制改密；
- 忘记密码：管理员在「成员管理 → 重置密码」，将按角色重置为对应默认密码；或直接在 MySQL 里改 `user` 表 `password` 字段（bcrypt 哈希）。

**Q7：新增了数据但页面不显示？**
- 确认当前连接的数据库里有数据（系统设置 → 关于系统可查看当前数据库名）；
- 注意**按角色过滤**：借用 / 周报 / 审批 / 入组离组等学生只看自己的；个人页面（我的项目 / 我的成果 / 我的任务）按当前用户过滤，新增时需选择负责人 / 完成人，否则列表查不到；
- 主进程改动未重启也会导致接口异常，重启应用再试。

**Q8：登录后提示必须修改密码？**
账号 `must_change_password=1`（新增 / 批量导入 / 重置密码后均会置位），修改密码后才能进入主界面，属正常流程。
